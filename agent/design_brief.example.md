# Frontend Design Brief

Use this as the `frontend.design_brief` source material or paste it into your task file.

## Desired feel

- Clean, calm, product-quality interface
- Strong information hierarchy
- One obvious primary action per screen
- Comfortable spacing and alignment
- Readable typography with disciplined scale
- Clear interactive states, loading states, empty states, and error states

## Visual rules

- Do not let the UI look like an untouched starter template
- Avoid weak CTA contrast or buttons that blend into the background
- Use consistent radii, shadows, spacing, and border treatment
- Keep motion restrained and purposeful
- Prefer simple layouts with a visible visual center of gravity
- Preserve accessibility and semantic structure while polishing visuals

## Functional review rules

- Browser console errors count as real bugs
- Failed network requests count as real bugs unless explicitly expected
- Missing labels, broken forms, unusable auth flows, or invisible focus states count as real bugs
- If the UI looks correct in code but wrong in the browser, trust the browser output
